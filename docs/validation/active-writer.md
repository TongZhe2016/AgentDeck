# Active Writer 接管与 Fork（2026-10-09）

检测到其他端写入者时，输入区只显示“接管会话”。点击后，成功则恢复模型／思考强度／权限、消息输入和附件，同时显示 Fork；仍被占用则提示“有其他用户正在使用”，并提供重试接管和 Fork。接管保留原 ID、草稿和附件，重新读取最新历史；Fork 复制已存历史到独立会话，原会话草稿仍可恢复。

Codex 0.161.0 的外部空闲写入者可能仍持有写入锁，thread/read 此时返回 notLoaded。服务排除自身已加载会话后，以写入锁文件存在作为占用提示，原生 thread/resume 决定是否可接管。当前原生协议没有强制夺取存活写入者的接口；写入权释放后可成功接管。原生 thread/fork 可在原会话被占用时创建分支。

验证结果：

- 服务端 17 项测试通过。覆盖外部空闲写入者检测、读取不取得写入权、占用时返回指定提示、Fork 新 ID、接管成功及自身写入者识别、已加载列表分页、无关错误保持原含义。
- 真实 Codex 0.161.0 与服务 HTTP 接口联调通过：两套 app-server 对同一合成会话竞争，原写入者存活时接管被拒，Fork 包含原历史，原写入者退出后成功接管。模型端点仅为本地合成 HTTP 服务，无收费模型调用。
- Android debug 与设备测试 APK 构建通过。API 36 模拟器 7 项测试通过，覆盖单按钮初始状态、接管成功恢复输入、被拒后的提示和 Fork、发送时遇到新占用保留中文草稿、原有历史续聊和连接行为。
- 横屏、两倍字体、深色模式、关闭系统动画下 3 项接管／Fork 测试通过；输入区可滚动，按钮可操作。
- 测试 HTTP 服务改按 UTF-8 字节数读取请求体，解决中文消息按 Content-Length 读取为字符而等待超时的问题。

日志、合成环境和截图位于忽略的 `.local/active-writer/`。
