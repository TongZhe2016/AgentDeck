# 引导与排队消息（2026-10-16）

电脑端使用 Codex 原生 `turn/steer` 与 `thread/queue/add`。引导加入当前轮次；队列由 Codex 在当前轮次完成后自动取下一条，不依赖手机停留或连接。空闲时按当前执行设置正常开始新轮次。排队消息可单独移除；取消活动轮次会暂停队列，待发消息保留，可点“恢复排队”继续。

每次提交先保存请求 ID、实际发送模式和附件引用，再跨原生进程边界。引导记录不夺取当前轮次的执行／审批归属；原生队列启动后，通过 `userMessage.clientId` 绑定独立执行。重复请求只返回已有记录。服务重启后先核实原生队列／历史，显式恢复保留的队列，不重新添加请求。现有数据库仅增加 `mode`、`queueId` 两个字段，保留已有数据。

- `npm --prefix host-service test`：23 项通过，新增引导归属与去重、队列等待／移除／独立执行、超时核实、旧数据库升级与重启恢复四项行为测试。
- 真实 Codex 0.161.0 + HTTP API + 本地合成 Responses 端点：引导保留原 turnId，排队等待原轮次完成后自动进入新 turnId；队列图片出现在原生历史；移除的队列消息未执行；重复确认请求未重复加入队列。合成端点共收到三次模型请求，未调用收费模型。

- 真实 Codex 取消当前轮次：已排队消息仍在原生队列中，状态保持 waiting_queue；通过恢复接口完成该消息，未重新添加队列项。

Android 默认使用排队。在首页“消息发送设置”或会话输入区“后续消息”中可随时选择排队／引导，选择保存在此设备并适用于所有主机。执行中发送按钮显示实际模式；已提交的消息保持原模式。排队消息显示在正文末尾，可单独移除、核实或恢复。引导被明确拒绝时保留草稿与附件；网络失败后确认送达沿用原请求 ID 和原发送模式，即使默认设置已改变也不重新解释该次请求。
