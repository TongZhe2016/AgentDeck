# 流式显示与当前会话跟随（2026-10-09）

通过掌舵发起的执行继续使用 Codex 原生 agentMessage delta，经持久事件流传到手机。手机将片段约每 80 ms 合并显示，完整消息到达时立即校正；接收端使用有界背压，避免片段密集时主动断线重放。完整消息已应用后，迟到的 delta 和 started 不再覆盖它。

当前打开的会话约每秒读取正文增量，重读最后一轮并按需补齐新增轮次，每页最多 20 轮。只读接口使用原生分页游标；先取得最新锚点再读取增量，避免取锚点期间新增的轮次被跳过。无需恢复会话或争抢 Active Writer。客户端按轮次和消息 ID 合并，保留更早历史、草稿及尚未落盘的流式片段；未变化的正文不重复解析或写缓存。离开会话停止跟随，断线重连后从已有锚点继续，失败保留内容并提示重试。

## 原生能力边界

真实 Codex 0.161.0 的独立 app-server 读取者无法获得其他进程尚未完成的 agentMessage delta：生成中只能看到已存用户消息，回答完成后才可读取已存回复。同一 app-server 的原生事件则能立即提供文字片段。因此手机执行支持流式显示，其他客户端执行支持按落盘消息自动跟随，目前不能保证跨进程逐字显示。完成事件丢失时，已存完整消息仍可通过正文跟随校正。若模型自身中断且没有完整回答，则保留已经接收的内容。

## 验证

- 服务端 18 项测试通过；新增覆盖选定会话的增量读取、先取锚点的顺序及离线积压分页。
- Android debug 和设备测试 APK 构建通过；第一轮 6 项测试覆盖流式显示、已有连接／目录行为及 Active Writer。加入主动断线后，流式与连接 3 项测试再次通过：完整回答前可见片段、连续 150 个片段不引发队列溢出重连、断线后补齐无完成事件的完整回复、迟到旧事件不破坏完整消息、外部已存回复自动跟随、退出停止读取；列表和原历史读取次数不增加。
- 本机真实 Codex + 本地合成模型 SSE + 服务 HTTP 接口验证：结束前收到真实 SSE 片段，断开订阅后服务仍保存完整事件，updates 返回最终回答，另一 app-server 通过同一游标补齐外部回复及新增轮次。无收费模型调用。
- 原始日志及合成脚本在忽略的 `.local/streaming/`。
