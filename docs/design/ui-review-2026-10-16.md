# AgentDeck 全局 UI 审查：让工作内容占主位

日期：2026-10-16。审查基线：`c0ccdae`。本次交付审查与设计草图，未修改 Android 界面或交互行为。

结论：当前主要矛盾是功能随开发逐项增加，却大多获得了独立的一行、按钮或卡片。应先重排操作层级，再调整间距。聊天正文、项目与会话、文件内容应获得最多空间；配置、维护和常驻说明应让位。

## 依据与边界

逐页阅读首页、工作台、会话列表、聊天、执行设置、执行过程、审批、Changes、Graph、Diff、密钥、SSH 终端、SFTP 与安装流程的 Compose 源码，并查看已有小屏、深色、大字号横屏截图。截图来自不同开发阶段，仅用于核实局部组件；当前导航、按钮和状态以基线源码为准，不把旧截图的底部导航等已移除内容算作当前问题。

本机电脑控制工具拒绝读取 `com.openai.codex` 窗口，因此未直接观察此 Mac 的 Codex 界面。OpenAI [Codex 官方介绍](https://openai.com/index/introducing-the-codex-app/)作为项目／任务组织方式的参考，不据此声称当前桌面版有某个具体图标布局。其可借鉴之处是围绕任务上下文组织对话与代码审阅；本报告中的控件位置是针对 AgentDeck 的设计判断。

使用 UI/UX 技能的一般层级、逐层展开和 Compose 指导。关键词检索未给出适用于本项目的层级设计命中，不把网站排版建议套入手机。Canvas 运行目录与 SDK 在当前环境不可用，因此配套提供自包含 [交互设计草图](ui-review-2026-10-16.html)。草图为合成内容，未复制真实会话或凭据。

草图已检查脚本语法、本地链接和状态切换逻辑；当前电脑工具未能打开浏览器窗口，尚未做真实浏览器排版验收。它用于讨论层级，不能代替 Compose 改版后的设备验证。

## 操作层级如何判断

先问用户此刻要完成什么，而非按功能有多少个来平分空间。

- **持续工作**：读回复、输入和发送、打开项目／会话、阅读 Diff、使用终端。这些是页面主体。
- **当前任务所需**：执行中停止、排队消息、审批、失败后重试。仅在相应状态出现，但出现时必须直接可见。审批按钮保留文字，不能降成含义不明的小图标。
- **工作参数**：模型、思考强度、权限、引导／排队模式。保留当前值和便捷入口；完整选项在面板内。完全访问等有实际意义的状态仍要明确显示。
- **偶尔维护**：添加另一台主机、重连、克隆、导出公钥、服务安装、清缓存。放上下文菜单或详情页。首次使用时，添加主机／安装可以成为主操作；完成后降级。

视觉大小、颜色、位置、出现时机共同表达主次。图标能减少文字和横向占用，但不能独自解决纵向布局。

本轮没有使用行为统计；使用频率的判断来自手机 Codex 工作台的产品目的，任务状态则以现有功能为依据。

## 最先改：聊天输入与消息操作

### 抬头先回答“我正在哪个会话工作”

工作台将主机信息、会话、Changes、Graph 近似等分剩余宽度；会话标题却在聊天列表最早位置，向下阅读后会离开屏幕。结果是次要导航一直占位，而当前项目／任务上下文不够明确。

建议顶部主显示当前项目／会话名，主机与连接状态作次级信息。Changes 以带变更数量的图标直达，Graph 收入代码操作菜单；进入代码页后能直接返回对话。这样保留常用代码审阅入口，又让历史浏览降低权重。不新增第二条常驻导航栏来换取标题位置，否则只是把占用转移到另一行。

### 输入区从四层收敛成两层

[WorkspaceScreen.kt](../../app/src/main/java/com/worldcopy/agentdeck/feature/workspace/WorkspaceScreen.kt) 的 Chat 输入区目前依次铺开模型／强度／权限行、后续消息设置按钮、输入框／发送行、附件／草稿说明行；接管后还可能增加全宽 Fork。模型栏本身最低 48dp，输入旁发送最低 56dp。这些结构在无附件时也常驻；60% 高度上限只能让工具区内部滚动，不能解决主次。

建议输入框独占第一层，第二层为紧凑工具栏：附件图标、模型与强度摘要、权限入口、发送及其模式入口。去掉常驻“草稿保存在此设备”，仅在保存异常时提示。引导／排队在运行中由发送动作旁的模式选择体现；全局设置继续保留默认值，已发消息不随设置更改。模型长名称省略但可展开查看实际 ID；完全访问保留红色标记和可读名称。

普通字号可先按约 120–144dp 的无附件输入区打样，相比目前约 220–240dp 的堆叠结构有明显优化空间。这是结构估算和设计目标，未通过新版 Android 测量，不能当作已实现收益。附件、长草稿和大字号应自然增高。软键盘打开时，优先压缩解释性文字，保留最近消息、任务状态和输入。

**运行中仍能发送后续消息。停止是旁边独立的直接操作，不能用停止按钮替掉引导／排队的发送入口。**

### Fork 降低视觉权重，保留能力

当前每条可分叉回复后附加最低 48dp 的“Fork 新对话”文字按钮；接管成功后还有全宽 Fork。这是本轮结束后的偶发操作，却被赋予接近发送的存在感。

建议最新回复末端使用中性分叉图标；历史回复的 Fork 可通过消息操作菜单取得，避免一屏出现多段绿色操作文字。接管后的 Fork 放到会话更多菜单。新建结果仍需明确打开独立会话，不能把复制或重试冒充 Fork。

实施时把操作放入消息边缘的留白或共同操作区域，不新建全宽按钮行；代码块和表格不能被悬浮图标遮住，窄屏必要时收入更多菜单。如果每条消息换成图标后仍新增一条 48dp 工具栏，纵向节省几乎为零，应重新安排位置。触控区域不能压成图标本身的 20dp。

### 执行、停止和排队合并表达

当前执行摘要、取消本轮、每条排队卡的状态／全文／“移除排队消息”各占区域。建议一行展示当前执行摘要与停止图标；紧邻显示“排队 N 条”，默认只预览最近待发内容，点开查看完整队列。单条移除用有名称的关闭图标，恢复排队在暂停时提供文字操作。

“送达待核实”“排队已暂停”必须明显保留，不能为了紧凑折叠掉需要用户决策的状态；排队全文仍可展开，不能静默截断后无法阅读。

## 随后改：首页与会话入口

### 首页让“继续工作”比“管理电脑”更突出

[ProjectsScreen.kt](../../app/src/main/java/com/worldcopy/agentdeck/feature/projects/ProjectsScreen.kt) 顶部在 App 栏之后又有大标题、统计、添加主机、同步项目、长按说明。已有自动同步机制时，手动同步和添加另一台主机仍占据显眼位置。首页未提供直接的最近会话入口，而是每次从折叠树展开。

建议无主机时保留明确的添加主机主按钮；已有主机时，标题收敛到一行，添加主机与手动同步放顶部图标／菜单。增加一个简短的“最近会话”入口区，或返回首页时保留刚才的展开位置，让继续原任务少走几步。这个入口属于后续设计，需要从已有会话时间元数据确定顺序；本轮没有假称已实现。

主机菜单增加可见的更多图标，长按仍可作为快捷方式。这样 SSH 工具、重连和编辑能被发现，无需常驻“长按主机…”说明。连接失败时在对应主机行直接提供重试；正常时只显示紧凑状态。

### 把嵌套卡片改成有层级的列表

当前主机和项目行均最低 80dp，项目缩进 16dp，会话再缩进 32dp；两侧页面留白、卡片边距和图标继续叠加，最重要的会话标题可用宽度反而最少。

保留“主机 → 项目 → 会话”的逻辑。主机用分组标题与状态，项目用低强调度列表行，会话用普通可点击行；减少层层边框和重复图标底色。项目名称为主，完整路径在同名消歧或详情时展开，平时显示精简路径。普通字号的主机／项目可从 56–64dp 起打样；大字号用最小高度与自适应增长，不固定裁切。会话当前仅一行省略，可在需要时给标题两行，空间应先从重复元数据和缩进中回收。

### 会话列表的搜索表达需要更直接

[WorkspaceScreen.kt](../../app/src/main/java/com/worldcopy/agentdeck/feature/workspace/WorkspaceScreen.kt) 的 SessionList 把新建、搜索框、“搜索标题 / 刷新”“搜索正文”、范围 Chip 和同步时间堆在列表前。搜索和刷新被合为一个文字动作，用户需要先理解接口区别。

建议标题行放新建图标；搜索框承载搜索入口，标题／正文作为清楚的搜索范围选项，刷新使用独立图标。项目范围内不再重复每条会话的完整项目路径；“受管理会话／已有会话”降为详情，只有外部占用、离线等会影响下一步的状态留在行内。正文扫描进度和继续扫描仍明确提示，不能把按需搜索伪装成即时全量结果。

## 参数、代码阅读和 SSH

### Catalog 任意增长时，执行设置必须分层

[ExecutionSettingsSheet.kt](../../app/src/main/java/com/worldcopy/agentdeck/feature/workspace/ExecutionSettingsSheet.kt) 在同一 LazyColumn 内先列出全部模型，思考强度和权限排在模型之后。模型越多，用户只想改权限也得滑过全部型号。这是自定义 Catalog 支持后可直接出现的问题。

建议主面板只显示当前模型一行、当前强度和权限；点击模型进入独立的可搜索列表，支持显示名和实际 ID。刷新收为图标，来源说明只保留一份；不按猜测的厂商或硬编码名单分类。当前滑杆、宿主机提供的思考档位以及完全访问警示可以沿用，优先解决长列表抢占空间。

### Git 保留紧凑做法，收起仓库配置与导出

Changes 和 Graph 顶部都把仓库路径作为常驻可编辑字段。Changes 还在列表前展示筛选框、分支、提交总数、上游、完整根目录和查询时间。建议以项目／分支摘要开头，路径点击编辑，其余仓库信息进详情；搜索需要时展开。文件差异仍为主内容。

[DiffViewer.kt](../../app/src/main/java/com/worldcopy/agentdeck/feature/workspace/DiffViewer.kt) 将导出和引用放在独立按钮行，而每个代码行的旧／新行号通过换行上下排列。建议引用收为顶部图标，导出进更多菜单；旧／新行号在同一行对齐。长代码在自动换行与横向阅读之间提供明确选项，不能只缩小字体。截断／二进制等内容限制继续可见。

Graph 已采用单行标题、相对时间和点击展开提交详情，执行过程也已采用逐层展开。这两处方向正确，保持，不再重新做大卡片。

### SSH：终端和文件常用，安装按阶段突出

[RemoteToolsScreen.kt](../../app/src/main/java/com/worldcopy/agentdeck/feature/remote/RemoteToolsScreen.kt) 将终端、SFTP 文件、安装服务放为同级 Chip。日常使用时，安装的频率远低于前两者；文件页还常驻大路径输入框及前往／上级／主目录／刷新四个文字按钮。大字号横屏截图中，列表首屏只剩很少空间。

建议终端／文件作为日常切换，安装移到主机更多菜单；新电脑进入安装流程时，再突出上传安装操作。服务连接异常不能一律称为“未安装”，也可能是目录、端口或启动问题，应提供“查看服务设置／安装”入口。

文件页使用可点击编辑的路径摘要，将上级和刷新并入同一工具栏，主目录放路径菜单。目录／文件用图标区分，去掉每行“文件夹 ·”“点击打开”；文件大小转为易读单位，点击下载的含义由下载图标和无障碍名称表达。详细时间可按需查看。终端正常连接时不必再用一行“SSH 终端”重复标题；保留断开／退出状态及必要辅助按键。

安装页在开始前保留目标账号、数据目录、端口与环境要求，运行中突出阶段与进度；原始日志默认可展开，失败时自动展开。目标和有实际后果的信息不能全部藏起来。安装成功后的主操作是连接工作台。

## 低优先级及应保留的设计

密钥页已有“公钥按需展开、删除和重命名进菜单”，方向正确。后续可把复制公钥作为行内快捷图标，分享／导出放更多菜单，减少单独“查看公钥”按钮行；不值得先于聊天重做。主机表单的高级服务设置已按需展开，继续沿用。

审批和待处理需要相反的处理：真正要用户决策时，允许／拒绝／回答应保留可读文字与足够空间，任务或命令上下文要清楚。不能因为审批不常发生就把操作藏到菜单。正常“在线”“已上传”等弱化为行内信息；失败、需要审批、送达未知等保持明确。颜色用于这些差异，而非每个次要动作都使用品牌绿。

全局尺寸原则：正文维持可读字号；收缩的是多余包装、说明和层级。Android 独立图标控件仍保留至少 48×48dp 触控区域、清楚的无障碍名称与按压反馈，见 [Compose 默认无障碍行为](https://developer.android.com/develop/ui/compose/accessibility/api-defaults)。视觉图标可以是 20–24dp，不能把多个扩大后的点击范围叠在一起。大字号允许换行／增高，不用固定高度强行压缩。

## 实施顺序与验证重点

第一批做聊天两层输入区、消息 Fork、执行停止／排队表达，以及去除草稿常驻说明。它们对每天每轮对话都有收益。

第二批做首页标题与操作降级、树列表压缩和会话搜索，再做 SSH 文件工具栏与安装入口分级。维持功能入口和当前数据归属，减少回到任务所需步骤。

第三批分离模型选择列表、简化 Git 顶部信息、整理密钥辅助操作。沿用已经紧凑的 Graph、执行详情和正文排版。

实现后按具体失败验收：375dp 小屏＋软键盘确认回复仍有可读空间；2 倍字号横屏确认消息／文件列表没有被工具区挤没；运行时实际发送引导／排队并停止当前轮次，确认发送入口和队列状态仍清楚；审批和未知送达状态确认不能被隐藏；长模型名、大 Catalog、长路径与多附件确认可展开且不覆盖正文。这些是下一轮改版的验证重点，本次未执行 Android 改版测试。
